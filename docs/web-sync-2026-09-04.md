# Android web synchronization — 4 September 2026

## Scope and behavior

Adds Narratrace Daylight, Narratrace Marigold and Narratrace Lamplight to the existing Account > Profile and preferences > App appearance picker. Shared web background, foreground, muted text, accent, border and error tokens are mapped to opaque Material roles. Existing appearance names and local preference storage remain compatible. This is installation-local appearance, as before; no new account API or cross-device theme synchronization is introduced.

The server remains authoritative for paid AI processing (30%, reviewed to 40%, then 50%). Native clients do not calculate allowances or grant exceptions. Existing API v1 RATE_LIMITED/429 and SERVICE_UNAVAILABLE/503 envelopes preserve the customer-safe message and support reference. Existing older Android versions can decode these envelopes; no forced upgrade is needed for server enforcement.

Text response and narrative actions now show failed processing messages instead of silently discarding them. Text drafts and their idempotency keys remain intact on failure. Interview video uses the existing protected-upload message formatter so processing pauses remain visible. Nia companion behavior and saved-content access are unchanged.

A 429 without Retry-After stops background upload retries while retaining encrypted originals; manual “Retry protected uploads” remains available. This conservative behavior also applies to transient 429 responses without a retry timer. Timed 429 responses and 503 retain existing retry behavior. Local media is removed only on an explicit server acknowledgement of durable storage and verified integrity. No new server codes, endpoints, permissions or persistent resources are introduced.

## Accessibility

New palettes explicitly define Material foreground/container roles, including error, inverse, outline and elevated surfaces. Unit regression checks cover normal text at 4.5:1 and control boundaries at 3:1 across eight surface roles per palette, plus nine foreground/control pairs. Picker buttons use full-width wrapping labels and expose selected semantics; existing 16sp-minimum typography and platform font scaling remain. Processing failures use an accessible dialog with an assertive live region, independent of scroll position.

No Android emulator or physical device was attached during synchronization. TalkBack, large-font layout, touch-target and rendered screen checks must be performed on a device before a native store release. Token tests do not constitute whole-app accessibility certification.

## Security gate

Reviewed changed paths: no authentication, native credential storage, TLS, MFA, authorization, billing or financial-record writes changed. All cap enforcement remains server-side; customer UI cannot raise a cap. No secrets, private media, provider credentials or customer data were used in verification. Failed uploads retain encryption and existing preservation acknowledgements. No dependencies added. Background no-timer 429 retry loops are stopped; manual retries continue through server admission. Existing unknown-error and malformed-response handling fails closed.
